# Antelope webauthn changelog

## v4.0.0

### Major

- Removed deep imports across the package and replaced them with a **single public entry point**.
- All modules are now exported from a unified `index.ts`, allowing consumers to use **destructured imports** rather than importing from internal paths.

Example:

```ts
import {
  antelopeSign,
  authenticatorAssertion,
  authenticatorAttestation,
  classifyWebAuthnCredential,
  createAntelopePublicKey,
  createAntelopeSignature,
  verifyAntelopeSignature,
} from "antelope-webauthn";
```

This refactor:

- simplifies the public API
- prevents reliance on internal file paths
- improves long-term maintainability
- allows internal refactoring without breaking downstream applications

---

### Standardized Export Names

The exported utilities are now standardized and re-exported through the main `index.ts`.

```ts
export { default as antelopeSign } from "./_utils/antelope-sign.js";
export { default as authenticatorAssertion } from "./_utils/authenticator-assertion.js";
export { default as authenticatorAttestation } from "./_utils/authenticator-attestation.js";
export { default as classifyWebAuthnCredential } from "./_utils/classify-web-auth-cred.js";
export { default as createAntelopePublicKey } from "./_utils/create-antelope-publickey.js";
export { default as createAntelopeSignature } from "./_utils/create-antelope-signature.js";
export { default as verifyAntelopeSignature } from "./_utils/verify-antelope-signature.js";
```

This provides a **clear and predictable API surface** for developers consuming the package.

---

### Internal Project Structure

All internal build utilities and implementation files have been moved into a dedicated `_utils` directory.

The package structure is now organized as:

```text
src/
  index.ts
  _utils/
    antelope-sign.ts
    authenticator-assertion.ts
    authenticator-attestation.ts
    classify-web-auth-cred.ts
    create-antelope-publickey.ts
    create-antelope-signature.ts
    verify-antelope-signature.ts
```

Benefits of this change:

- cleaner and more maintainable project layout
- clear separation between **public API** and **internal implementation**
- safer internal refactoring without impacting consumers

---

### WebAuthn Attestation → Antelope Public Key

The library now derives an **Antelope-compatible public key** directly from the **WebAuthn attestation response**.

During credential creation:

1.  A WebAuthn attestation is generated by the authenticator.
2.  The attestation response is parsed.
3.  The COSE public key is extracted.
4.  The key is converted into an **Antelope `PUB_WA` formatted public key**.

This improvement enables applications to:

- generate Antelope-compatible keys directly from WebAuthn authenticators
- simplify the credential creation flow
- remove additional manual key conversion steps
- integrate WebAuthn authentication with Antelope transaction signing

---

### Summary

This release focuses on **cleaner architecture, improved developer ergonomics, and a more stable public API**.

Key improvements include:

- removal of deep imports
- unified package entry point
- standardized export naming
- improved internal project structure
- direct Antelope public key derivation from WebAuthn attestations
